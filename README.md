## 基础策略摘要

手机很少连 Wi-Fi，按中国移动 5G。稳定优先。坏了才换，不比谁更快。

- **ChatGPT、xai、官**：香港 → 日本 → 新加坡 → 美国。
- **xai**：Cursor、Grok、X、Grok bot 同一组。
- 沿用检测页 `http://www.gstatic.com/generate_204` 和 `timeout=5`；ChatGPT链为 `interval=180`，其他链为 `interval=600`。这是基础健康探测，不保证业务故障后 5 秒恢复，也不能证明 ChatGPT 所有功能可用。
- 使用有序 `fallback`；实际接替与回切取决于手机客户端版本和当时的健康结果。
- **狗狗**：不在自动链。不要点「测试」。不要改回自动测速。
- 首页选「官」，工作模式选「配置」。

## 手机更新

推送后：小飞机 → 配置「官」→ **更新**。

主要可见策略仍为 ChatGPT、xai、官。ChatGPT 使用隐藏的「ChatGPT-香港」等子组；xai、官沿用「奶昔-香港」等子组。实际显示随客户端健康结果变化，不保证始终为香港。不用改节点订阅。

## 验证与回退

执行 `python3 tests/check_config.py` 可检查组引用、地区顺序、规则优先级、既有规则保留以及非目标分流未变化。该脚本是静态检查，不是 Shadowrocket 原生解析器或手机实测。

GitHub 更新不等于手机已加载：手机配置更新后，才会使用本版。当前无法远程确认手机安装的客户端版本、启用的配置、蜂窝/Wi-Fi 连接、登录、流式回答、上传及语音表现，不将仓库检查通过表述为手机验收通过。

若本版出现异常，可恢复本轮基线 `archive/guan-20261109.conf` 或回退到维护前提交；无需重置节点订阅、账号或证书。

## 使用方式与试运行边界

手机只需更新现有“官”配置；无需手动测速、选择优选节点或调整小飞机参数。新增子组均为隐藏，不增加首页操作负担。

首轮使用尽量保持同一种常用网络：若蜂窝信号稳定，可先用蜂窝正常工作，避免一轮对话中主动往返切Wi-Fi。没有实测证据证明必须永久弃用家里/单位的稳定Wi-Fi；蜂窝信号差时应使用更可靠的网络，不强制5G。

GitHub端无法读取手机节点健康历史或远程实测蜂窝线路。本轮完成的是候选结构检查、参数试运行准备和静态回归；手机稳定节点排名、实际恢复时延与电量收益仍未完成实测。用户正常使用的反馈是后续调整依据，不要求用户操作诊断菜单。

如出现更频繁断线、切换、耗电或原来能用的功能异常，维护方将主入口恢复为本轮基线，用户仍只需更新配置，无需重置订阅或账号。没有手机实测证据前，不继续缩短超时、增大调整范围或删除候选。
